# Basic Usage Examples

This directory contains simple, single-module examples that demonstrate the fundamental usage patterns of Brockhoff Cloud Terraform modules across AWS, Azure, and GCP.

## Overview

These examples showcase:
- Standardized module interfaces across cloud providers
- Common configuration patterns
- Integration with terraform-external-context
- Cost-effective defaults for development environments
- Security best practices

## Examples

### AWS Basic Compute
- **Path**: `aws/`
- **Resources**: EC2 instance, security group, KMS key
- **Estimated Cost**: $15-25/month
- **Complexity**: Beginner

### Azure Basic Compute  
- **Path**: `azure/`
- **Resources**: Virtual machine, network security group, key vault
- **Estimated Cost**: $20-30/month
- **Complexity**: Beginner

### GCP Basic Compute
- **Path**: `gcp/`
- **Resources**: Compute instance, firewall rule, KMS key
- **Estimated Cost**: $18-28/month
- **Complexity**: Beginner

## Quick Start

1. Choose your cloud provider directory
2. Copy the example to your workspace
3. Customize the variables
4. Deploy the infrastructure

```bash
# Example for AWS
cp -r examples/basic-usage/aws my-aws-compute
cd my-aws-compute

# Customize variables
cp terraform.tfvars.example terraform.tfvars
# Edit terraform.tfvars with your values

# Deploy
terraform init
terraform plan
terraform apply
```

## Common Variables

All examples use these standardized variables:

```hcl
# Required variables
name_prefix = "myorg-dev"  # Generated by terraform-external-context
environment_type = "Development"

# Optional customization
instance_type = "small"  # small, medium, large
monitoring_enabled = false
backup_enabled = true

# Tags (generated by terraform-external-context)
tags = {
  Project = "BasicExample"
  Owner   = "DevTeam"
  Environment = "development"
}
```

## Cross-Cloud Consistency

These examples demonstrate how the same configuration pattern works across all three cloud providers:

| Feature | AWS | Azure | GCP |
|---------|-----|-------|-----|
| Compute | EC2 t3.micro | Standard_B1s | e2-micro |
| Storage | EBS gp3 | Premium SSD | pd-standard |
| Networking | VPC + Security Groups | VNet + NSG | VPC + Firewall |
| Encryption | KMS | Key Vault | Cloud KMS |
| Monitoring | CloudWatch | Azure Monitor | Cloud Monitoring |

## Security Features

All examples include:
- Encryption at rest using cloud-native KMS
- Network security controls (security groups/NSGs/firewall rules)
- Least-privilege IAM policies
- Secure defaults for public-facing resources

## Cost Optimization

Examples are optimized for cost-effectiveness:
- Smallest viable instance types for development
- Efficient storage configurations
- Optional monitoring (disabled by default for dev)
- Automatic shutdown scheduling for non-production

## Testing

Each example includes validation:

```bash
# Validate configuration
terraform validate

# Check plan
terraform plan

# Run automated tests
make test
```
